## Verified findings

### 1. Repetitive JSON request body decoding across handlers

`internal/api/bench_jobs.go:88-139; internal/api/build.go:185; internal/api/hf.go:111; internal/api/service.go:703; internal/api/settings.go:57` _(finding cited `internal/api/bench_jobs.go:88`)_ · severity: medium · found by 1/5 run · duplication

Five separate json.NewDecoder(r.Body).Decode calls in different handlers follow identical pattern: decode request body into struct. Each handler repeats the Content-Type check and decoder pattern without shared abstraction.

> **Verification:** Five handlers across five files use identical json.NewDecoder(r.Body).Decode(&struct) pattern with http.Error wrapper. Four handlers (build, hf, service, settings) include Content-Type check before decoding; bench_jobs.go handles do not but still repeat the decoder structure without shared abstraction. The code duplication is real and would require multiple similar edits if any change to this pattern is needed.

### 2. Duplicated shared library copying logic (2 near-identical loops)

`internal/builder/builder.go:506-532` _(finding cited `internal/builder/builder.go:509-532`)_ · severity: medium · found by 1/5 run

Two nearly identical loops checking for .so files in libDir and binDir (lines 509-518 and 523-532) that could be unified into a single function accepting directory paths as parameters.

> **Verification:** Two nearly identical loops copying .so files from different directories. Loop 1 (lines ~506-519) reads libDir for .so files and copies them to outDir. Loop 2 (lines ~520-532) reads binDir using the exact same logic and copies matching .so files to outDir with identical logging format. The loops can be unified into a single function accepting directory paths as parameters.

### 3. VRAM estimation function duplicated between models package and huggingface client

`internal/models/vram.go:18; internal/huggingface/client.go:185-187` _(finding cited `internal/models/vram.go`)_ · severity: low · found by 1/5 run · duplication

The `EstimateVRAM()` function in vram.go (line 20) computes `sizeBytes * 1.1 / (1024*1024*1024)` with a fixed overhead constant. An almost identical `estimateVRAM()` function exists in internal/huggingface/client.go (line 145) that performs the same calculation without the constants as local vars. These should be unified to one shared helper.

> **Verification:** The finding is confirmed. File: internal/models/vram.go contains `EstimateVRAM(sizeBytes int64) float64` at line 18 that computes `float64(sizeBytes)*1.1/(1024*1024*1024) + vramOverheadGB`. File: internal/huggingface/client.go contains `estimateVRAM(sizeBytes int64) float64` at line 185-187 that computes `float64(sizeBytes) * 1.1 / (1024 * 1024 * 1024)`. These are substantially identical implementations of the same formula, differing only in one operation (adding overhead vs not), and both use a hardcoded magic number pattern `(1024*1024*1024)` for the byte-to-GB conversion. They should be unified into a shared helper function to eliminate duplication.
