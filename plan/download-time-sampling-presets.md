# Download-Time Sampling Presets

Replace the frozen, committed sampling-preset snapshot
(`internal/models/sampling_presets_data.go`, generated by
`make scrape-sampling-presets`, last run 2026-05-20, unsloth-only,
exact-match lookup) with per-model preset discovery that runs when a
model is **downloaded** (and backfills models already on disk). A model
released yesterday — e.g. Qwen 3.8 27B — should surface publisher
presets minutes after download, from any quantizer org, with no
rebuild and no rescrape.

Motivating discovery (researched 2026-08-14): the ecosystem largely
solved this after our scraper was written. llama.cpp merged
**GGUF-embedded sampling defaults** (`general.sampling.*` header keys,
PR ggml-org/llama.cpp#17120, 2025-11-25); `convert_hf_to_gguf.py`
populates them from `generation_config.json`, and unsloth, bartowski,
and lmstudio-community GGUFs all ship them now (verified live against
`unsloth/Qwen3.8-27B-GGUF`: `temp=1.0, top_p=0.95, top_k=20`). The
best source for most new models is **the file we just downloaded**.
Unsloth's docs additionally became machine-readable (GitBook `llms.txt`
index + `.md` suffix per page) and remain the best source for
mode-split variants (thinking vs. instruct) and params vendors never
publish (`min_p`, `presence_penalty`).

---

## Current state (what actually exists — corrects common misconceptions)

- The "build-time doc scrape" is neither build-time nor doc-based:
  `scripts/scrape-sampling-presets/main.go` is a **manual codegen
  step** (`make scrape-sampling-presets`) that enumerates HF repos
  under `author=unsloth`, fetches the *base* model's
  `generation_config.json` plus the GGUF repo's README (regex parse),
  and writes a committed Go map. Nothing in CI, goreleaser, or
  `go:generate` re-runs it.
- Lookup is a bare exact-match on `Model.ModelID`
  (`internal/models/sampling_presets.go:28`). 128 `unsloth/*` repos,
  217 variants, frozen. Any other quantizer or any repo published
  after the snapshot gets nothing.
- Consumers: model-config UI (`internal/api/service.go:783`,
  `web/templates/partials/model_config.html:372-415`) and the
  capabilities contract (`internal/api/capabilities.go:66`
  `buildSampling`). Chosen values persist as `ModelConfig` pointer
  fields → preset INI (`internal/models/preset.go:167-184`) and
  per-request proxy injection (`internal/api/proxy.go:286-321`).
- Download completion already does post-download enrichment (mmproj,
  MTP heads, GGUF metadata) in `onDownloadComplete`
  (`internal/api/hf.go:347-406`) — the natural hook. The second
  ingest path, `Registry.ScanModels()` (`internal/models/registry.go:759`),
  picks up manually-copied files and must get the same treatment;
  `BackfillGGUFMeta` (`registry.go:506`) is the established pattern.

## Goals

1. **Presets attach at download time** — when a GGUF finishes
   downloading, resolve presets from a source chain and persist them
   on the model record; the config UI picker and
   `capabilities.sampling` work unchanged.
2. **Any source org** — unsloth, bartowski, mradermacher,
   lmstudio-community, ggml-org, vendor-official GGUFs: no hardcoded
   publisher list in the lookup path.
3. **Backfill existing models** — models already in the registry (and
   manually-copied ones found by `ScanModels`) get presets without
   re-downloading.
4. **Offline-tolerant** — the primary source (GGUF header) needs no
   network; network sources are best-effort with timeouts and never
   block or fail a download.
5. **Provenance visible** — every preset keeps `Source` + `SourceURL`
   so the user can verify where a number came from; heuristics are
   labeled as such.
6. **Retire the codegen** — delete the committed 78 KB map and the
   scraper once backfill proves out (78 KB of mostly-dead data in
   every binary, guaranteed stale).

## Non-goals

- LLM-based extraction from arbitrary model-card prose (still no
  structured convention on HF; deterministic parsing only).
- A hosted/shared preset database of our own.
- Auto-*applying* presets without user action — presets remain
  suggestions in the picker; blank config still means "server
  defaults" (which, nota bene, now includes GGUF-embedded defaults —
  see §Source 1).
- Scraping Ollama/LM Studio registries in v1 (see Deferred).

## Source chain (ranked; stop at first hit per field, merge variants)

### 1. GGUF header `general.sampling.*` — primary, local, offline

`ParseGGUFMeta` (`internal/models/gguf.go`) already walks the KV
header at download/scan time. Extend it to read
`general.sampling.{temp,top_p,top_k,min_p,penalty_repeat,penalty_last_n,mirostat,…}`
and emit one preset `{Name: "default", Label: "Model-embedded
default", Source: "gguf"}`. Zero network, works for every GGUF
converted after ~Nov 2025 regardless of publisher.

Interplay note: llama-server itself now applies these header defaults
when no CLI flag overrides them, and our preset INI only emits
sampling keys the user explicitly set — so for new GGUFs the embedded
default is already *active*; this source is about **surfacing** it in
the UI, not changing behavior. Also read
`general.base_model.0.{name,repo_url}` here — it feeds source 3.

### 2. Unsloth docs (`llms.txt` + per-page `.md`) — variant enrichment

The old `docs.unsloth.ai` HTML is gone (301 → `unsloth.ai/docs`,
GitBook). GitBook officially serves `https://unsloth.ai/docs/llms.txt`
(page index) and raw markdown by appending `.md` to any page URL
(e.g. `https://unsloth.ai/docs/models/qwen3.8.md`). Each "How to Run"
page has a consistent `### Recommended Settings` markdown table,
including thinking/non-thinking columns and params GGUF headers lack
(Qwen 3.8: instruct mode `temp 0.7, top_p 0.8, presence_penalty 1.5`
— none of which is in the GGUF header, which carries thinking-mode
values only).

- Fetch + cache `llms.txt` (TTL ~24 h, cached under
  `<dataDir>/cache/`), keep entries whose path matches
  `/docs/models/` (both `models/<slug>` and `models/tutorials/<slug>`).
- Match downloaded repo → docs page by normalized family token:
  strip org, `-GGUF`, quant suffixes, size (`27B`, `A3B`), then score
  against page slugs/titles. Best-effort; no match → skip silently.
- Parse the settings table into variants (`thinking`,
  `non-thinking`, `default`), `Source: "unsloth-docs"`,
  `SourceURL: <page URL>`. This replaces the README-regex heuristics
  wholesale — tables beat prose regex.

### 3. Base model `generation_config.json` — fallback for older GGUFs

For pre-Nov-2025 quants with no header keys: resolve the base repo
(GGUF `general.base_model.0.*`, else HF API
`/api/models/{repo}?expand[]=cardData` `base_model`), then
`GET https://huggingface.co/{base}/resolve/main/generation_config.json`.
Reuse the scraper's existing `genConfig` parse + "token-IDs-only =
miss" rule. Gated repos (`meta-llama/*`, `google/*`): retry against
the `unsloth/` mirror of the same name before giving up.

### 4. Legacy `params` file in the quant repo

Pre-2026 unsloth GGUF repos ship an Ollama-style `params` JSON
(`resolve/main/params`) carrying unsloth's own `min_p` /
`repeat_penalty` recommendations. One cheap GET; parse if present,
`Source: "params"`.

### 5. Labeled heuristic — not implemented in v1

Family heuristic (reasoning arch → `temp 0.6 / top_p 0.95`; instruct
→ `0.7 / 0.8`) marked `Source: "heuristic"`. Deferred entirely:
silence has been acceptable so far and a wrong confident-looking
number is worse than a blank field. Revisit only if the first three
sources leave real gaps in practice.

Merge rule (reuses scraper semantics): later sources never overwrite
a field an earlier source set for the same variant name, but may
back-fill nils and add new variants. Dedupe, `default` sorts first.

## Design

### New package `internal/presets`

- `type Fetcher struct { hf *huggingface.Client; cacheDir string; … }`
- `Fetch(ctx, repoID string, meta *models.GGUFMeta) []models.SamplingPreset`
  — runs the chain above; per-source timeout ~10 s, whole-fetch
  budget ~30 s; every network miss is a debug log, never an error to
  the caller.
- `SamplingPreset` struct stays where it is (`internal/models`) and
  gains new `Source` values
  (`gguf | unsloth-docs | generation_config.json | params`).
  (Implementation note: per-preset `FetchedAt` was dropped —
  `Model.PresetsCheckedAt` covers staleness with less churn.)

### Persistence

Add `SamplingPresets []SamplingPreset` to `Model`
(`internal/models/registry.go:59-92`), persisted in
`<dataDir>/config/models.json` like every other model field. JSON
unmarshal tolerates absence, so no migration needed —
`BackfillGGUFMeta` precedent.

`LookupSamplingPresets(repoID)` (exact-match map) is replaced by
reading `m.SamplingPresets` at the two consumer sites
(`service.go:783`, `capabilities.go:67`). During the transition
release, fall back to the static map when the field is empty; delete
map + scraper + Make target the release after backfill ships.

### Hooks

1. **Download**: in `onDownloadComplete` (`internal/api/hf.go`),
   after `meta.ApplyTo(m)` and `registry.Add(m)`, spawn
   `go s.enrichPresets(m)` — async so a slow/offline fetch never
   delays registration. On completion, update the record via the
   registry (same lock discipline as mmproj auto-association).
2. **Scan**: `ScanModels` gains the same async enrichment for newly
   discovered files (it already reconstructs `ModelID` from the
   `org--repo` dir name at `registry.go:825`).
3. **Startup backfill**: once per boot, walk the registry for models
   with empty `SamplingPresets` and no prior attempt marker
   (`PresetsCheckedAt time.Time` on `Model` prevents hammering repos
   that legitimately have nothing), enrich serially with jittered
   pacing — reuse the scraper's fetch etiquette (UA, `HF_TOKEN`
   bearer, retry-on-429).
4. **Manual refresh**: `POST /api/models/{id}/refresh-presets`
   clears `PresetsCheckedAt` and re-runs the chain; small ⟳ button
   next to the picker in `model_config.html`. Covers "unsloth just
   published the docs page for the model I grabbed on day one".

### UI / API deltas (small)

- Picker template and `applySamplingPreset` JS: unchanged (schema is
  the same). Update the label tooltip text ("scraped from the model's
  HuggingFace page" → source-aware).
- `buildSampling` card-selection and per-field resolution: unchanged.
- When presets exist but config is blank and the GGUF has header
  defaults, show a one-line note that the model's embedded defaults
  are already active — avoids "why does it sample fine with blank
  fields" confusion.

## Phases

1. **GGUF header source + persistence** — extend `ParseGGUFMeta` with
   `general.sampling.*` + `general.base_model.*`; add
   `Model.SamplingPresets` / `PresetsCheckedAt`; wire
   `onDownloadComplete` + `ScanModels`; consumers read the field with
   static-map fallback. *Deliverable: download Qwen 3.8 27B, see the
   embedded default preset in the picker.*
2. **Network sources** — `internal/presets` fetcher with unsloth-docs
   (llms.txt + `.md` table parse), `generation_config.json`, `params`
   chain; caching, timeouts, etiquette. *Deliverable: Qwen 3.8 shows
   thinking + instruct variants incl. `presence_penalty 1.5`.*
3. **Backfill + refresh** — startup backfill, manual refresh
   endpoint/button. *Deliverable: pre-existing registry models grow
   presets on next boot.*
4. **Retirement** — delete `sampling_presets_data.go`, the scraper,
   and the Make target; fix `capabilities_test.go`'s hardcoded-repo
   `t.Skip` pattern to use injected fixtures instead of the static
   map.

## Testing

- Golden-file tests for the unsloth `.md` table parser (commit
  fixture pages; qwen3.8, a tutorials-path page, a page with a
  single-mode table).
- GGUF header source: synthesize a tiny GGUF fixture with
  `general.sampling.*` keys (the existing GGUF test helpers can
  emit KVs).
- Fetcher chain: httptest server per source; assert merge/no-overwrite
  semantics, 404 = silent miss, 429 retry, gated-repo mirror retry.
- Registry: backfill idempotence (`PresetsCheckedAt` respected),
  scan-path enrichment for a manually-placed file.

## Risks

- **Docs-page matching is fuzzy** — wrong family match would attach
  wrong numbers. Mitigate: require a high match score, keep
  `SourceURL` visible, and never let docs values *overwrite* GGUF
  header values for the same variant (merge rule).
- **GitBook format drift** — `llms.txt`/`.md` are officially served,
  but table shape may change; golden tests + silent-miss keep drift
  from breaking downloads.
- **Registry write races** — async enrichment mutating `Model` needs
  the registry's existing locking, not direct struct writes.
- **HF rate limits during backfill** — serial + jitter + honor 429;
  worst case backfill finishes on a later boot.

## Deferred / future

- **Ollama registry** as source 5 (public OCI registry:
  `ollama.com/api/tags` → manifest → `vnd.ollama.image.params` blob;
  verified working) — solid data but needs fuzzy HF-name→library-name
  mapping; add if the first three sources leave real gaps.
- **LM Studio `model.yaml`** — richest format (conditional
  thinking-mode fields) but no public raw endpoint; revisit if
  modelyaml.org grows a fetchable catalog.
- Community databases: none exist as of Aug 2026 — the
  GGUF-embedded-metadata effort became the ecosystem's answer, which
  is why source 1 is primary.
