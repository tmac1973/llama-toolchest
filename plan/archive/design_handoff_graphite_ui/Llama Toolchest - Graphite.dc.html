Quickstart

  1. Build llama.cpp. Go to Builds, pick a profile that matches your hardware (CUDA, ROCm, Vulkan, CPU), and start a build. Builds are cached and reused.
  2. Download a model. On Search HF, search for a GGUF repo and download a quant (Q4_K_M is a good balance).
  3. Enable it. On Models, flip the "On" switch for the model(s) you want served.
  4. Tune for VRAM. Click Configure to adjust Context Size and KV Cache Quant; watch the VRAM Est. column update.
  5. Start the server. Go to Server and click Start, then force-load a model or let the router load on first request.
  6. Send a request. Use the OpenAI-compatible endpoint, passing a model's public name in the model field.

Core concepts

Enabled vs loaded

Enabled
The model is in the llama.cpp preset and advertised via /v1/models. Enable as many as you like — it uses no VRAM.
Loaded
The weights are resident in GPU VRAM and ready to serve. Only a limited number load at once (Max Loaded).

Max Loaded

Caps how many models are simultaneously resident. When the cap is hit, the router unloads the least-recently-used model. Set to 0 for unlimited.

Model config

Most config changes require a server restart to take effect. Sampling params apply per-request with no restart.

Speculative Decoding

Predict multiple tokens per step for a speedup with no quality change. Draft Model uses a smaller same-architecture model; N-gram modes use pattern matching with no extra model.

Troubleshooting

Start button does nothing
No successful build exists. Go to Builds and build llama.cpp first.
Out of VRAM
Lower GPU Layers, reduce Context Size, enable KV Cache Quant, or lower Max Loaded.
